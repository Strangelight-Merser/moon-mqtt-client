## 合并阻塞

### A1 — P1：Linux 上 TLS 动态加载失败

位置：`third_party/async-tls/src/openssl.c:88`、同文件 137–139 行。
新代码把 `SSL_CTX_set_max_proto_version` 放入必须成功的 `dlsym` 列表。
OpenSSL 3.0 中它是调用 `SSL_CTX_ctrl` 的宏，没有该动态符号。

在官方 `ubuntu:24.04` 镜像内直接调用动态加载器得到：

```text
SSL_CTX_ctrl: present
SSL_CTX_set_max_proto_version: MISSING
```

因此加载器会返回 4，影响所有使用该依赖的 TLS 连接，不只 mTLS。
macOS 当前加载系统 LibreSSL，不能用其通过结果推断 Linux OpenSSL 可用。

修复要求：移除不必要的协议上限及其动态导入；确有需要的宏须使用实际可加载的
OpenSSL 接口。用 Linux native 客户端完成单向 TLS 和 mTLS 正反例后再验收。

依据：[OpenSSL 3.0.13 ssl.h.in](https://github.com/openssl/openssl/blob/openssl-3.0.13/include/openssl/ssl.h.in#L1371)。

### A2 — P1：客户端身份强制限制 TLS 1.2

位置：`third_party/async-tls/src/identity.mbt:112`、`openssl.c:441–446`。
每次加载客户端身份都会把最高协议版本设为 TLS 1.2，公开文档没有该限制。

独立服务器设置 TLS 1.3-only，并要求客户端证书；相同证书的 Python 客户端成功
协商 `TLSv1.3`，MoonBit 客户端退出 1，服务端报告 `UNSUPPORTED_PROTOCOL`。

修复要求：恢复协议协商，增加 TLS 1.3-only 的真实成功收发回归；不得通过降低
broker 协议要求使测试变绿。TLS 1.3 拒绝客户端身份的验证应观察应用读写或 MQTT
连接结果，不能假设所有服务端拒绝都在客户端握手返回前到达。

### A3 — P1：公开错误类型被 Closed 掩盖

位置：`client.mbt:124–129`、`runtime.mbt:105–112`。
监督任务在失败退出时先设置 stopped 并唤醒连接等待者；等待者返回 `Closed`，
掩盖了 dial 路径准备返回的错误。

使用实际 broker，通过 `examples/test_driver` 的公开 API 路径观测：

| 条件 | 约定 | 本轮实际结果 |
|---|---|---|
| 私钥文件不存在 | InvalidConfig | ClientError.Closed |
| 加密私钥 | InvalidConfig | ClientError.Closed |
| 错误服务器 CA | TlsFailure | ClientError.Closed |

修复要求：保存并向等待者传播终止原因，正常关闭才返回 Closed；增加对公开错误
类型的断言。当前拒绝测试只验证退出码非零，不能证明错误契约实现正确。

### A4 — P1：Linux 默认 OpenSSL 无法生成测试证书

位置：`tests/integration/run.py:118–122`；独立 TLS 的 `scripts/gen-testdata.sh`
也有同类命令。
`openssl x509 -not_before ... -not_after ...` 在本轮 Ubuntu 24.04 / OpenSSL
3.0.13 中实际返回 1，输出 `x509: Use -help for summary.`。
当前 CI 使用 apt 安装 OpenSSL，因此现有 macOS 测试通过不能保证该矩阵通过。

修复要求：使用目标环境支持的证书签发方式，如 `openssl ca` 的起止时间选项，
保持“确实已过期”的验收条件；不得删除过期证书测试。

依据：[OpenSSL 3.0 x509 命令选项](https://docs.openssl.org/3.0/man1/openssl-x509/)。

### A5 — P2：注册表验收仍依赖本地 TLS 源码

位置：`tests/consumer_smoke.py:23–26`。
脚本在处理 `--registry` 前无条件查找本地 TLS 模块，并调用没有默认值的 `next()`。
在仅有本库验收脚本及 manifest、没有 vendored 或相邻 TLS 源码的临时目录中运行
`--registry`，在访问注册表前即报 `StopIteration`。

修复要求：只在本地 workspace 模式查找该目录；注册表模式完全独立。
之后在没有 `moon.work`、源码副本和继承 `MOON_WORK` 覆盖的环境中验证已发布依赖。
本轮未发布两个新版本，注册表安装成功不能记为已完成。

## 额外覆盖缺口

- `test_mtls_cert_acl_isolation` 的实际权限验证双方都是 Paho，不能证明 MoonBit
  客户端的证书权限隔离；并发身份测试又使用两个独立 driver 进程，不能验证同一
  进程的 TLS context 是否串用。需增加同进程双身份和 MoonBit 参与 ACL 的断言。
- EMQX 就绪探测失败分支出现未关闭 SSLSocket 的 ResourceWarning，需清理 probe。
- TLS 1.3-only、错误类型及 Linux native 回归在当前测试中没有被正确覆盖。
