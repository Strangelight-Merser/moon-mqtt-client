## R1 — P1：TLS 单元测试遗漏 TCP 关闭，CI 的 FD 检查中止

位置：`third_party/async-tls/src/identity_test.mbt:52`、`:75`；
`third_party/async-tls/src/openssl.mbt:633`；`.github/workflows/check.yml:19`。

按 CI 环境运行 `MOONBIT_ASYNC_CHECK_FD_LEAK=1 ./scripts/check.sh`，TLS
测试进程报告 **17 个 Socket 泄漏**，以 SIGABRT 终止，`moon test` 返回 255。
进一步仅运行已有的正常握手测试：

```sh
MOONBIT_ASYNC_CHECK_FD_LEAK=1 ./scripts/moon.sh test --target native \
  --package Strangelight-Merser/async-tls \
  --filter 'tcp mtls handshake with client identity'
```

仍稳定报告 **2 个 Socket 泄漏**。

`accept_server` 和 `connect_client` 创建 TCP 后只返回 TLS 包装对象，调用方
失去了关闭 TCP 的句柄；TLS 的 `close()` 释放 SSL/context，不负责关闭底层流。
握手异常路径也没有配套 TCP 清理。本轮 MQTT mTLS 短测 FD 稳定，不能把这里的
测试资源泄漏直接表述成 MQTT 正常收发必然泄漏。

修复建议：让测试作用域持有 TCP，在正常结束、握手失败和取消路径都关闭它；
保留现有 FD 检查并重跑单例及全套测试。
证据：`macos-check.log`、`single-tls-test.log`。

## R2 — P1：workspace 构建产物路径变化，演示和场景冒烟无法启动

位置：`tests/scenario_smoke.py:26`、`examples/mqtt_demo/demo.py:40`，以及
新增加的 `moon.work:1`。

干净 workspace 构建成功，真实产物位于：

```text
_build/native/debug/build/Strangelight-Merser/moon-mqtt-client/examples/mqtt_demo/test_device/test_device.exe
```

两个入口仍查找：

```text

```

因此场景冒烟抛出 `FileNotFoundError`；README 中的四场景演示命令退出 2 并提示
missing executable。即使解决 R1，完整检查仍会在这里失败。保留旧 `_build`
可能掩盖此问题，或运行到上个版本的二进制。

修复建议：根据实际 workspace 构建结果定位程序，统一两个入口；必须在无旧
构建缓存的目录复跑，不要复制旧二进制来补路径。
证据：`macos-runtime.log`、`demo.log`。

## R3 — P2：注册表验收的 moon run 缺少入口参数

位置：`tests/consumer_smoke.py:72`。

在没有 `third_party/async-tls`、相邻 TLS 仓库或 `moon.work` 的独立目录运行
`--registry`，并注入无效的 `MOON_WORK` 检查隔离行为。当前代码已清除
`MOON_WORK`、不再无条件查找本地 TLS 源码，但执行的是：

```text
moon run
error: the following required arguments were not provided:
  <PACKAGE_OR_MBT_FILE|-e <SCRIPT>>
```

CLI 返回 2，Python 入口返回 1。此问题发生在消费程序运行前，即使后续依赖
发布完成，当前命令仍不能完成注册表验收。

修复建议：补齐工具链要求的入口参数，并在不含任何本地源码覆盖的临时模块中
重新运行 TCP 和 mTLS 消费者。
证据：`registry-only.log`。

## R4 — P2：TLS 1.3 身份拒绝仍被归类成 ProtocolError

位置：`runtime.mbt:35`、`:55`，`client.mbt:145`；
约定见 `docs/API-CONTRACT.md:65`。

独立运行 TLS 1.3-only、要求客户端证书的 Mosquitto，通过公开 API 观测：

| 客户端身份 | 实际结果 |
|---|---|
| 未提供证书 | ProtocolError，退出 1 |
| 不受信 CA 签发的证书 | ProtocolError，退出 1 |
| 已过期证书 | ProtocolError，退出 1 |

这些连接确实被拒绝，没有认证绕过；问题在于错误分类与文档的 `TlsFailure`
约定不符。TLS 1.3 的服务端身份拒绝可在客户端 TLS 构造返回后的 MQTT 首次读写
时显现。当前转换仅包围 `Tls::client`，后续 TLS 错误进入
`client_error_of` 的通用 `ProtocolError` 分支。

修复建议：在首次 MQTT CONNECT/CONNACK 的 TLS 读写失败路径保留 TLS 错误
类别；增加对上述 TLS 1.3 拒绝条件的公开错误类型断言，避免只检查非零退出码。
证据：`tls13-error-types.log`。
