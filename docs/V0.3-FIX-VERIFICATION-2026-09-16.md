### R1

`third_party/async-tls/src/identity_test.mbt` 的测试连接同时持有 TLS 与 TCP；成功路径关闭两者，构造失败由 `errdefer tcp.close()` 清理。双平台均以 `MOONBIT_ASYNC_CHECK_FD_LEAK=1` 执行整个 workspace 测试。

结论限于本仓库内的 TLS 副本。相邻独立目录本轮未单独运行测试，未将本仓库结果外推为其验收通过。

### R2

第一份快照中的递归回退确实可选中旧扁平目录文件；验收期间工作区删除了该回退，最终结论依据第二份快照。

独立临时目录矩阵覆盖 workspace / standalone 两种布局，以及“仅旧产物存在”“当前与旧产物同时存在”两种状态，共四种组合，均通过。当前目标缺失时返回预期的缺失路径；两种产物同时存在时仅选择当前配置对应的路径。探针没有执行占位文件。

证据：`path-probe.json`。旧快照中的 P2 已被最新修复关闭，不作为当前未解决问题。

### R3

隔离验收目录仅复制原样的 `moon.mod`、`tests/consumer_smoke.py`、`tests/integration/run.py`，无本地 TLS 源码，并故意设置无效 `MOON_WORK`。脚本成功清除该变量；`moon update` 成功，`moon run .` 越过入口参数解析，实际失败为：

```text
Failed to resolve registry dependency `Strangelight-Merser/moon-mqtt-client`
for module `acceptance/consumer`: no version satisfies requirement `0.3.0`
```

这只能证明原参数错误已修复，不能证明发布包可安装。所需依赖及 MQTT 版本发布后仍须运行 `tests/consumer_smoke.py --registry`。本轮 workspace 独立 TCP、mTLS 消费者均通过。证据沿用第一份快照的 `registry.log`；两份快照间消费者脚本与模块清单未改变。

### R4

除了原样运行回归用例，还以 TLS 1.3-only、强制客户端证书的真实 Mosquitto，独立调用公开 API：缺失证书、不受信证书、过期证书均失败关闭且返回 `TlsFailure`。新增 TLS `close_notify` 后关闭连接的用例也通过。

证据：`tls13-probe.json` 与集成日志。拒绝探针中的非零驱动退出为预期结果。
