# H01: Receive Maximum and non-PUBLISH progress

The supplied native draft compiled without adaptation against the fixed
toolchain. The original production implementation failed the SUBSCRIBE and
UNSUBSCRIBE assertions independently. Its third draft test also aborted while
unwrapping the missing selection. The public API peer reproduced the fault after
observing second-publication admission (`pending=2`, `business=1`) and both
subscription admissions (`pending=4`). Its four-second peer watchdog expired
before the driver's fifteen-second operation budget; a request timeout did not
advance the scenario.

The fix replaces the single parked item with a private deferred PUBLISH buffer.
Moving an item into that buffer does not free a business slot. Both stores share
the original `send_capacity` budget. With credit available the original business
order is preserved. With credit exhausted only the earliest non-PUBLISH request
passes; QoS0 remains behind earlier publications. Reserved control slots and
control priority are unchanged. Abort clears both stores.

The independent peer holds the first PUBACK through SUBSCRIBE, UNSUBSCRIBE, their
acknowledgements and a further SUBSCRIBE barrier. Seeing that barrier before the
second PUBLISH proves the scheduler continued after SUBACK/UNSUBACK without
incorrectly restoring PUBLISH credit. All three subscription requests use the
business queue. Only then does the peer return the first PUBLISH credit.

This implements [MQTT 5 section 3.3.4, MQTT-3.3.4-8](https://docs.oasis-open.org/mqtt/mqtt/v5.0/mqtt-v5.0.html):
non-PUBLISH packets must not be delayed by exhausted Receive Maximum. No retry
policy, public API, SQLite schema, persistence transition or dependency changed.

Local macOS acceptance: 156 native tests, 13 MQTT5 runtime cases, 10 maintenance
cases, 5 recoverable QoS1 cases and 4 durable process cases passed. `moon check`
passed and regenerated tracked API files are byte-identical to baseline. Existing
assertions were retained; fixture edits only initialize the replacement private
field. Hosted platforms and the final frozen candidate remain separate gates.
