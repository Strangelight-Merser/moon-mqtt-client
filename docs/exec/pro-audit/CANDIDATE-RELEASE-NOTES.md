# Unpublished audit candidate

No formal version, registry upload, tag or release is created by this work.

When MQTT5 Receive Maximum is exhausted, queued SUBSCRIBE/UNSUBSCRIBE can now
pass blocked PUBLISH requests. PUBLISH order and subscription order are retained;
the original business capacity is shared with a bounded private deferred buffer.
Reserved protocol-control capacity remains separate. Native and public raw-peer
red/green evidence captures the original head-of-line blocking defect.

Private heartbeat state now uses named states; common white-box fixtures and
small process/evidence helpers reduce maintenance duplication without removing
independent protocol/broker/crash assertions. Retry policy, public API, SQLite
schema 2 and pinned dependencies remain unchanged.

Local and CI checks share Core/Integration/Release scenarios; default check stays
Integration. Candidate library consumers and a separately versioned recovery
operator ZIP are exercised in isolated consumers. Recovery mutation remains
experimental; outgoing durability does not imply a durable inbox or physical
execution. Current failure/security/support documentation states these limits.

Performance/resource and storage-error evidence are part of Release acceptance,
including exact durable transaction windows. ESP32 firmware and separate B2
consumer/evidence tools are prepared, with GPIO disabled until wiring review.
No new physical hardware acceptance claim accompanies this candidate.
